# C++17 后续审查与优化

## 范围与执行计划

本轮检查近期现代化后的线程、用户内存访问和文件系统边界。保留 Nachos
单处理器模拟、固定长度文件和各实验的接口，不增加依赖或替学生实现实验。

1. 先运行现有构建及测试，补充能复现问题的边界回归测试。
2. 修复文件头非法长度、文件读写非法偏移与长度加法溢出，使用 RAII
   管理读写临时缓冲区；保持磁盘布局不变。
3. 修复用户内存访问范围检查、字符串容量边界和无效地址导致内核断言的问题。
4. 明确 Join 仅允许已启动线程的单一内核调用者等待，返回后消耗目标指针；
   父子资格与可重复等待仍属于实验扩展。覆盖提前结束、未启动、并发等待及随机调度。
5. 在独立临时目录中运行测试，避免格式化开发目录的 DISK；空测试筛选应失败。
6. 通过独立代码与架构审查、全模块构建、回归测试和编译器静态分析验证。
7. 根据独立审查补充链表移动所有权、空元素析构、新线程入口延迟回收、
   锁误用诊断和网络包头拷贝；位图使用无符号掩码表达位操作。

计划由主执行者编写；独立 code-reviewer / architect 审查结果及最终验证记录
见下文。现有 `.omx` 状态不属于修改范围。

## 审查发现与修复

| 优先级 | 问题 | 本轮处理 |
| --- | --- | --- |
| HIGH | UserMem 的失败路径进入异常处理器并终止内核；地址加法可能溢出 | 非 trapping 字节翻译，检查地址范围，失败返回 false；明确部分拷贝与 TLB miss 契约 |
| HIGH | 文件大小未限制到固定的 30 个直接索引块 | 在计算、修改文件头与位图前拒绝负长度和超过 MaxFileSize 的长度；失败保持原状态 |
| HIGH | Join 无唯一回收者，未启动或多个等待者可永久阻塞、访问已释放对象 | 关中断后原子声明唯一调用者，检查线程已启动，等待与回收后恢复原中断状态 |
| MEDIUM | 文件读写接受负偏移，position + numBytes 可溢出 | 检查缓冲区与偏移，使用 fileLength - position 截断长度；临时缓冲区改用 unique_ptr |
| MEDIUM | List 默认移动复制节点指针，造成双重释放；空 payload 提前终止析构 | 用 std::exchange 转移所有权；按 IsEmpty 判断析构结束，处理自移动和非空目标 |
| MEDIUM | 连续首次运行的 detached 线程绕过延迟清理，覆盖待回收对象 | 复用 ReapFinishedThread，在调度恢复和新线程入口、开启中断前回收 |
| MEDIUM | LOG_ERROR 被调试标志过滤；空 LockGuard 静默跳过同步 | ERROR 始终输出；空锁指针立即断言，引用构造和析构去掉冗余分支 |
| MEDIUM | 字节数组强转 PacketHeader / MailHeader 指针违反 C++17 对象访问规则；包填充未初始化 | 使用 memcpy 拷贝头部，发送缓冲区零初始化，保持原协议布局 |
| LOW | 空测试筛选以成功退出；文件系统测试可能覆盖当前目录的 DISK | 空筛选与无效超时参数报错；每个子进程使用独立临时目录，使用单调时钟计时 |

另外修复 ReadString 对空字符串、恰好容纳结尾 NUL 的容量判断，增加文件头
大小、标准布局和 trivially-copyable 编译期约束，位图位操作明确使用无符号掩码。
README 改用仓库内相对链接，实验文档与当前 Join/UserMem 接口保持一致。

## 第二轮扩展计划

用户要求继续上述待办。本轮按三条互不重叠的实现路径执行：

1. 进程表：原子创建与登记，查询返回稳定持有句柄；父子等待、重复状态查询，
   明确线程完成句柄和地址空间共享所有权。
2. 线程与加载器：新增父线程专用、可重复等待的完成句柄，线程栈自动回收；
   保留原有消耗指针的 Join 接口。校验 NOFF 头、区间、文件长度和地址上界，
   验证失败不修改机器内存；运行生成的实际 MIPS 指令，覆盖驻留页 TLB 填充。
3. 设备与消息：按回调函数与参数精确取消待处理中断，设备销毁后继续运行；
   邮局工作线程退出后再销毁设备和信号量，销毁未消费的邮件对象。

各实现先补可验的回归用例，再做修改；主执行者负责公共构建、测试运行器与
文档集成，独立架构复审检查跨路径生命周期。保持磁盘与网络布局和 C++17，
不增加依赖。最终以全目标构建、常规及负向回归、UBSan、静态分析为验收证据。
完整 Swap 与页面置换继续按 Lab 3 的独立算法实验组织，本轮先验证驻留页的
实际加载与执行路径。

## 第二轮实现结果

| 待办 | 结果与接口 |
| --- | --- |
| PID 创建与登记的原子性 | 删除分离的 AllocatePid/RegisterProcess；CreateProcess 在关中断区创建并登记，容量耗尽返回空句柄 |
| 进程查询和删除的生命周期 | GetProcess 返回 shared_ptr；RemoveProcess 按对象身份匹配，旧句柄无法移除复用 PID 的新对象 |
| 父子进程等待与重复退出码查询 | 保存 weak_ptr 父身份，Wait/TryWait 接受父句柄，PID 复用不授予旧父权限；首次 Exit 生效并唤醒全部等待者 |
| 线程完成状态与栈生命周期 | 新 ThreadJoinHandle 保留完成状态，父线程可复制和重复 Join；线程结束后调度器回收栈，放弃所有外部句柄也不阻止回收 |
| 地址空间所有权 | Process 与 Thread 共享 AddrSpace；原 Thread.space 仅作兼容观察指针；离开地址空间时清除硬件映射，最后持有者退出不留下页表或 TLB 别名 |
| Console/Network 运行中销毁 | Interrupt::Cancel 精确匹配函数与参数，保留其余中断顺序，取消过程不推进时间；先取消回调，再关闭设备资源 |
| 邮局线程与未消费邮件清理 | workerStopped 握手与父线程 Join 独立，可由非创建者销毁；先停止工作线程，再取消设备回调并释放队列，MailBox 通过非阻塞移除释放每个 Mail |
| 邮局关闭入口竞态 | 停止标志和 activeClients 在关中断区校验，关闭期间新 Send/Receive 立即拒绝；所有现有外部调用者须由 owner 先停止并 join |
| NOFF 非法输入 | 验证完整头、魔数、固定入口、负值、虚拟/文件区间、段重叠与驻留大小；完整读入临时映像后才写入机器内存，错误由 IsValid/GetLoadError 报告 |
| 旧 NOFF 格式兼容 | 忽略空段未使用字段与 BSS 文件偏移，按魔数检测并无条件交换异字节序头；MIPS 指令和数据仍为小端 |
| 驻留页 TLB miss | 后备页表轮转充填，换出和上下文切换合并 use/dirty；切换后清空 TLB，已解决异常重试原指令，未映射地址不会无限重试 |

新回归入口位于 `join_regression.cc`、`process_regression.cc`、
`device_regression.cc` 和 `loader_regression.cc`，通过已有 `-T` 调度接入。
Python 测试运行器在临时目录生成 NOFF 文件，实际执行 OR、延迟槽、LW/SW、
分支判断和 Halt，无需安装交叉编译器。文档已同步新的父子等待、共享所有权和
驻留页 TLB 行为。

  第二轮限定范围的最终结论为 APPROVE。

本轮仍采用单个驻留用户映像，尚未实现物理页框隔离、多进程 Exec/Exit/Join
系统调用、非驻留页调入与 Swap/页面置换。进程和线程句柄解决对象生命周期，
不能替代物理内存隔离。完整算法与系统调用接入仍按 Lab 2/3 的任务继续。

PostOffice 销毁前必须停止并 join 现有外部调用者；本轮不替未结束的阻塞
Send/Receive 取消请求。worker 停止握手期间允许正常调度，资源销毁阶段通过
stopping 门禁拒绝新调用。非法用户指令访问仍遵循原实验异常策略，只有内核
UserMem 辅助函数提供非 trapping 失败返回。Linux 尚未在本轮实际验证。
